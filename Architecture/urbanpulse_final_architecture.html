Layer 3 — Processing Layer (Lambda Hybrid)

⚡ Real-Time — Apache Flink (PyFlink · local mode)

AQI Emergency — keyed state · AQI > 300 → alert ≤ 2 min
Traffic Gridlock — avg wait > 180s for 3 consecutive cycles
Bus Bunching — 2 buses same route within 200m for > 5 min
Event-time watermarks — handles out-of-order arrival
Bus GPS Enrichment — join GPS stream with route_schedule KTable
Output → urbanpulse.incidents

📦 Batch + Streaming — Apache Spark (PySpark · local[*])

Ward Energy — 15-min tumbling window · total kWh, avg PF, peak V per ward
Dual output — Kafka topic + Parquet (partitioned by ward_id, date)
Health Advisory SQL — 10-min rolling avg AQI per zone
Zone join — static zone_profile table (population, schools)
Filter rolling_avg_aqi > 150 → Update mode output
Output → urbanpulse.health_advisories + Parquet

🏛 Architecture Choice: Lambda Hybrid

UrbanPulse uses a Lambda Architecture with Flink for the speed layer (sub-2-minute AQI alerts, signal control) and Spark for the batch layer (15-minute ward aggregations, councillor reports). A pure Kappa approach was rejected because the government reporting mandate requires separate historical reprocessing with auditable batch runs — not streaming recomputation. The two layers share the same Kafka topics so there is no duplicate ingestion code.
